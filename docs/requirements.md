# 成果物②：AIデータカタログ 要件定義（第2版）

## 1. 目的
社内のデータセットを登録・検索できるカタログを作り、説明文・分類・機微度などのメタデータ付けをAIで自動化する。
人手のメタデータ整備が追いつかないという現場の課題を、「AIが提案し、人が承認する」形で解く。

## 2. 利用者と役割
| 役割 | できること |
|---|---|
| データスチュワード | データセットの登録・編集、AI提案の確認、承認、廃止（管理者を兼ねる） |
| 閲覧者 | 公開中のデータセットの検索・閲覧のみ |

- ログインした人だけが使える
- 役割はユーザーごとに1つ持つ

## 3. 対象データ（すべて架空の小売会社）
| データ | 主な列 | 想定する機微度 |
|---|---|---|
| 商品 | 商品ID、商品名、カテゴリ、価格 | 公開 |
| 店舗 | 店舗ID、店舗名、地域、開店日 | 社内 |
| 注文 | 注文ID、顧客ID、商品ID、数量、売上金額、注文日 | 機密 |
| 顧客 | 顧客ID、氏名、メール、電話番号、生年月日、居住地域 | 個人情報を含む |
| 従業員 | 従業員ID、氏名、メール、所属店舗、役職、給与 | 個人情報を含む＋機密 |

## 4. メタデータ項目（DMBOKの3分類）

### 4.1 データセット単位
| 分類 | 項目 |
|---|---|
| 業務メタデータ | 名称、説明、データドメイン（顧客・販売・商品・店舗・人事）、業務用語タグ、データオーナー、データスチュワード、機微度、利用上の注意 |
| 技術メタデータ | 件数、列数、ファイル形式、文字コード |
| 運用メタデータ | 出所（元のシステム名）、更新頻度、登録日、更新日、状態、承認者、承認日 |

### 4.2 列単位
| 分類 | 項目 |
|---|---|
| 業務メタデータ | 列の説明、機微度、個人情報かどうか |
| 技術メタデータ | 列名、型、欠損率、ユニーク数、サンプル値（最大5件、伏せたもの） |

### 4.3 機微度の区分
公開／社内／機密／個人情報を含む（データセットには複数付けられる。例：個人情報を含む＋機密）

## 5. 機能

### 5.1 登録（11/9〜15）
- CSVをアップロードすると、列名・型・件数・欠損率・ユニーク数を自動で読み取る
- CSVの原本は保存しない。保存するのは列の情報と、個人情報を伏せたサンプル5行だけ
- 業務メタデータは画面から手で入力する（11/16以降はAIが提案する）

### 5.2 承認の流れ（11/9〜15）
- 状態：下書き → 承認待ち → 公開 → 廃止
- 登録した人と承認する人は別にする（自分の登録は承認できない）
- 閲覧者に見えるのは「公開」のデータセットだけ

### 5.3 閲覧と見せ方の制御（11/9〜15）
- 一覧画面と詳細画面
- 名称・説明・列名などのメタデータは、公開中なら全員が見られる
- サンプル値は機微度に応じて閲覧者から隠す

| 機微度 | 閲覧者に見えるサンプル値 |
|---|---|
| 公開・社内 | 見える |
| 機密 | データセット全体で隠す |
| 個人情報を含む | 該当する列だけ隠す |

- この制御はアプリの画面だけでなく、SupabaseのRLSで強制する

### 5.4 検索（11/9〜15）
- 名称・説明・タグ・列名へのキーワード検索
- ドメイン・機微度・状態での絞り込み

### 5.5 変更履歴（11/9〜15）
- 誰が・いつ・どの項目を・何から何に変えたかを記録する
- 11/16以降は、AIの提案値と人の確定値の両方を残す

### 5.6 AIによるメタデータ提案（11/16〜22）
- データセットの説明、ドメイン、業務用語タグ、機微度、列ごとの説明・機微度・個人情報かどうかを提案する
- 提案は「AI提案」と分かる形で表示し、スチュワードが採用・修正・却下する
- AIの提案の採用率を測れるようにする

### 5.7 質問への回答（11/23〜29）
- 「この分析に使えるデータは？」という質問に、カタログの内容をもとに答える（RAG）
- 回答には根拠となるデータセットを示す
- 閲覧者には、公開中のデータセットだけを根拠に使う

### 5.8 用語集（余裕があれば）
- 用語と定義の一覧を持ち、タグと結びつける

## 6. AIの利用ルール
- AIの提案は、人が承認するまで公開しない
- AIに送るのは、データセット名・列名・型・統計値と、伏せたサンプル行だけ
- APIキーは環境変数で管理し、画面やログに出さない

## 7. 非機能要件
- 画面は日本語、PC優先
- データセットは50件程度まで
- Supabase・Vercelの無料枠内で動くこと
- 開発用と本番用のSupabaseプロジェクトを分ける。テストは開発用でのみ行う

## 8. 完了条件
- 5.1〜5.5がVercel上で動く（11/15まで）
- 5.6が動き、採用率が表示できる（11/22まで）
- 5.7が動き、テストがすべて通り、READMEとデモ手順がそろっている（11/29まで）
- 2つのアカウント（スチュワードと閲覧者）で、承認の流れと見せ方の制御を実演できる
