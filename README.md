# AIデータカタログ

社内のデータセットを登録・検索できるカタログ。メタデータ付けを「AIが提案し、人が承認する」形で進める。

- 要件：[docs/requirements.md](docs/requirements.md)
- 設計：[docs/design.md](docs/design.md)
- 技術：Next.js（App Router）、Supabase（Auth、Postgres、RLS）、Tailwind CSS、Claude API（`@anthropic-ai/sdk`）

扱うデータはすべて架空の会社「サンプルリテール株式会社」のもの。

## できること（11/9〜22 の範囲）

| 機能 | 内容 |
|---|---|
| CSV登録 | CSVをブラウザ内で読み、列名・型・件数・欠損率・ユニーク数を自動で読み取る。原本は保存せず、個人情報の列を `***` に伏せた先頭5行だけを保存する |
| メタデータの入力 | データセット（説明、ドメイン、タグ、オーナー、機微度など）と列（説明、機微度、個人情報かどうか）を手で入力する |
| 承認の流れ | 下書き → 承認待ち → 公開 → 廃止。登録者と承認依頼者は承認できない |
| 見せ方の制御 | 閲覧者には公開中だけが見える。サンプルは、機密なら全列、個人情報を含むなら該当する列だけ隠す。RLSで強制する |
| 検索 | 名称・説明・タグ・列名へのキーワード検索、ドメイン・機微度・状態での絞り込み |
| 変更履歴 | 誰が・いつ・どの項目を・何から何に変えたかを記録し、スチュワードに表示する。AI提案を判断したときは、提案値と確定値、判断（採用・修正・却下）も残す |
| AIによる提案 | 説明・ドメイン・タグ・機微度と、列ごとの説明・機微度・個人情報かどうかをAIが提案する。スチュワードが採用・修正・却下する（まとめて採用・却下もできる）。AIに送るのはデータセット名・列名・型・統計値と、伏せたサンプル値だけ |
| 採用率 | AI提案の採用率を、全体・プロンプトの版・項目ごとに表示する（スチュワードだけ） |

## セットアップ

### 1. パッケージ

```bash
npm install
```

### 2. Supabase（開発用プロジェクト）

1. Supabase で開発用と本番用のプロジェクトを分けて作る
2. `supabase/migrations/` のSQLを、ファイル名の順に SQL Editor で実行する（テーブル、権限、RLS、DB関数）
3. Authentication の設定で、新規登録（Allow new users to sign up）を無効にする
4. Authentication > Users で利用者を作る。デモとテストには次の3人が要る（自分の登録は承認できないため、スチュワードは2人）
   - 閲覧者 1人
   - スチュワード 2人：作成後、SQL Editor で役割を変える

     ```sql
     update public.profiles set role = 'steward' where id = '<利用者のID>';
     ```

   - 表示名は、作成時の User Metadata に `{"display_name": "スチュワードA"}` のように入れる（無ければメールアドレスの @ より前）

### 3. 環境変数

`.env.example` を `.env.local` にコピーして値を入れる。`.env.local` はコミットしない。

| 変数 | 用途 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Supabase の接続先 |
| `ANTHROPIC_API_KEY` | AI提案に使う Claude API のキー。サーバー側だけで使う（`NEXT_PUBLIC_` を付けない） |
| `AI_SUGGESTER` | `fake` にすると、AIを呼ばずに決まった提案を返す偽物を使う（APIキーなしの動作確認用）。Vercel の本番では使えない |
| `ALLOW_DB_TESTS` | `1` のときだけ DB のテストを動かす。開発用の `.env.local` にだけ書き、Vercel には設定しない |
| `TEST_VIEWER_*`、`TEST_STEWARD_*`、`TEST_STEWARD2_*` | DB のテストでログインするアカウント（開発用プロジェクトのみ） |

Vercel には本番用プロジェクトの `NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` と `ANTHROPIC_API_KEY` だけを設定する。

### 4. 起動

```bash
npm run dev
```

http://localhost:3000 を開き、作った利用者でログインする。

## 使い方

### データセットを登録して公開する（スチュワード）

1. 一覧の「CSVを登録」からCSVを選ぶ（UTF-8 か Shift_JIS）
2. 読み取り結果を確認する。個人情報の候補にはチェックが入っている。備考などの自由記述の列はプレビューを見て判断する
   - データセットの名称はAIに送られるので、機密情報（顧客名・個人名・取引先名など）を含めない
3. 「下書きを作成」を押すと編集画面になる。上部の「AIに提案させる」で提案を作り、項目ごとに判断する（下の「AI提案を使う」）。残りの項目（担当スチュワードなど）を入れて保存する
4. 詳細画面で「承認を依頼する」を押す。説明・ドメイン・機微度・担当スチュワード・全列の機微度がそろい、データセットと列の機微度が整合していないと依頼できない。未判断のAI提案が残っていても依頼できない
5. **別のスチュワード**でログインし、詳細画面で「承認して公開する」を押す

- 承認待ちのものは「差し戻す」、公開中のものは「修正のため下書きに戻す」で下書きに戻せる（理由は必須）。下書きに戻すと、再承認まで閲覧者からは見えない
- 公開中のものは「廃止する」で廃止できる。一度も公開していない下書きだけ削除できる
- 個人情報の列は、伏せた値を元に戻せない（原本を保存していないため）。必要なら新しいデータセットとして再登録する

### AI提案を使う（スチュワード）

編集画面の「AI提案」の枠で操作する。提案は採用するまでデータセットに入らず、採用した後も公開には承認が要る。

| 操作 | 結果 |
|---|---|
| AIに提案させる | 提案を作る。もう一度押すと、未判断の提案は新しい提案に置き換わる（採用率の計算からも外れる） |
| 採用 | 提案値をそのまま入れる |
| 修正して採用 | 値を直してから入れる。直した値が提案と同じなら「採用」として数える |
| 却下 | 値は変えない |
| まとめて採用／まとめて却下 | 未判断の提案をすべて採用または却下する。履歴には提案ごとに1行ずつ残る |

- 判断すると画面が更新され、下の編集フォームで保存していない入力は消える。先に判断してから手入力する
- 変更履歴（詳細画面）の「AI提案・理由」欄に「AI提案：◯◯ → 採用」のように出る
- ヘッダーの「AI提案の採用率」で、採用率（採用 ÷ 判断済み）と修正込み採用率を見られる

### 閲覧する（閲覧者）

- 一覧で、キーワード、ドメイン、機微度で絞り込める
- 詳細画面では、名称・説明・列などのメタデータはすべて見られる。サンプルは機微度に応じて「非表示（機密）」「非表示（個人情報）」になる

## サンプルCSV

`samples/` に5つのファイルがある。作り直すときは次を実行する（シード固定なので毎回同じ内容になる）。

```bash
npm run generate:samples
```

| ファイル | 想定する機微度 | 確認できること |
|---|---|---|
| `products.csv` | 公開 | 閲覧者にサンプルが全部見える |
| `stores.csv` | 社内 | Shift_JIS の読み取り。閲覧者にサンプルが全部見える |
| `orders.csv` | 機密 | 閲覧者にはサンプルが全部隠れる |
| `customers.csv` | 個人情報を含む | 閲覧者には氏名・フリガナ・メール・電話番号・生年月日の列だけ隠れる |
| `employees.csv` | 個人情報を含む＋機密 | 閲覧者にはサンプルが全部隠れる |

## テスト

```bash
npm test          # 単体テスト（CSVの読み取り、入力チェック、状態の判定、AI提案など）
npm run test:db   # DBのテスト（RLS、権限、承認の流れ、AI提案の判断と履歴）。開発用プロジェクトでのみ動かす
npm run lint
npm run build
```

`npm run test:db` は、`.env.local` に `ALLOW_DB_TESTS=1` と接続情報・3アカウントが揃っているときだけ動き、そうでなければスキップする。作るデータは名前に「[テスト]」が付き、終わると下書きは削除、公開したものは廃止にする（一度公開してから下書きに戻したものは削除できないため残る）。

テストでは本物のAIを呼ばない。単体テストは決まった返答を返す偽物のクライアントを使い、DBのテストは提案の内容を直接DB関数に渡す。APIキーなしで画面を確かめるときは `AI_SUGGESTER=fake npm run dev` で起動する。
